# Varimode: the PIC16F684 quantizer firmware

`varimode_fixed.asm` is this project's own firmware for the Modular in a Week Day 10 CV quantizer
board, written for this repository. `varimode_fixed.hex` is what it assembles to, and
`src/PaymentSchedule/VarimodeFirmware.hpp` is the same words as a C++ array, which is what Payment
Schedule embeds. Both are generated; edit the assembly and run

    make firmware

at the repo root (`tools/pic16asm.py` does the assembling, since there is no MPASM or gputils in
this build). `make test` checks that the committed `.hex` and header are what the assembly
assembles to.

What it is, and how it differs from the course's firmware, is in the header of the `.asm` and in
`docs/PaymentSchedule.md`. The tables in it are generated by `tools/varimode_tables.py`.

## The course's firmware is not here

`varimodequantizer_100` (`.asm` and `.HEX`, Rev 1.0, 2010-05-29) came with the Modular in a Week
course material. It names no author and states no licence, so it is **not** in this repository and
never should be: Payment Schedule loads it at runtime from a path the player picks, and a patch
stores only the path. `.gitignore` refuses it. `tests/Pic16/test_varimode.cpp` runs it, and checks
the emulator against an independent interpreter of its source, when `VARIMODE_HEX` and
`VARIMODE_ASM` point at the files, and prints SKIP when they do not.

The assembler is checked against it the other way round: given the course's `.asm`, `pic16asm.py`
produces its `.HEX` word for word, all 1118 of them (including the `SUBLW .259` that MPASM
truncates to 3, which the course's tables depend on).
